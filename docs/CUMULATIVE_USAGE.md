# 누적 사용량 모드

QuotaDeck 0.2는 기존 **잔여 리밋**과 별개인 **누적 사용량** 모드를
제공한다. 설정 창의 `표시 정보`에서 모드를 고를 수 있으며, 계정 정렬
방식(`고정`/`스마트`)은 두 모드에 공통으로 적용된다.

## 지원 범위

| 서비스 | 현재 구현이 읽는 데이터 | 토큰·모델 | 일별·월별·최대 1년 | 기간별 비용 쌍 |
|---|---|---:|---:|---:|
| Codex | 이 기기의 `sessions`와 `archived_sessions` JSONL | 지원 | 지원 | 명시적 API-key 신호일 때만 `LIST` 환산 |
| Claude Code | 이 기기의 `projects` 응답 메타데이터 JSONL | 지원 | 지원 | 명시적 API-key 신호일 때만 `LIST` 환산 |
| Cursor | 기본은 N/A. token-stats/서버 Usage export가 계정·시각과 함께 있을 때만 활성화 | 조건부 | 조건부 | 조건부 |
| Grok Build | 개별 세션의 공식 `grok usage` 총계는 조회 가능하지만 합산하면 fork/resume 사용량이 중복될 수 있음 | 세션 inventory만 | 기본 화면은 N/A; 보존된 external OTel v1 이벤트를 별도 공급할 때만 가능 | N/A |

이 표의 “지원”은 **현재 로컬 프로필/기기에 보존된 기록**을 뜻한다. 계정
전체 또는 조직 전체 청구 원장을 뜻하지 않는다. 정확한 계정 범위 데이터는
서비스별 관리자 API가 필요하다. OpenAI Enterprise Analytics/조직 Usage,
Anthropic Usage & Cost, Cursor Admin API에는 관리용 경로가 있지만 QuotaDeck
0.2 런타임은 관리자 키를 수집하거나 저장하지 않는다.

Grok Build의 external OTel 전송은 기본적으로 꺼져 있고 활성화 이후의
이벤트만 수집된다. 과거 기록을 소급 복원하지 않으며, 보존 기간은 사용자가
운영하는 collector/storage 설정에 달려 있다. 개별 `grok usage` 결과는 정확한
세션 총계와 비용 tick을 보여 주지만, 세션의 `updatedAt` 하나만으로 모든
turn을 특정 날짜에 귀속하지 않는다.

## 일별·월별 계산

설정 창에서 누적 비교 기간을 **일별** 또는 **월별**로 고른다. LCD의
`THIS`, `AVG`, Bar, 비용과 캐릭터 반응은 모두 같은 선택 기간을 사용한다.

| 선택 | `THIS` | `AVG` | 비교가 활성화되는 조건 |
|---|---|---|---|
| 일별 | 현재 시스템 시간대의 오늘 달력일 토큰 | 오늘을 제외한 이전 완료일 평균 | 이전 완료일 최소 7일 |
| 월별 | 이번 달 1일부터 현재까지의 토큰(MTD) | 이전 완료 월들의 월평균 | 이전 완료 월 최소 1개월 |

- 모든 이벤트 시각은 현재 시스템 시간대로 변환한다. DST가 있는 시간대도
  이벤트별로 변환한다.
- 일별 평균은 최초 보존 기록 이후 사용이 없던 완료일을 0으로 포함하되,
  최초 기록 이전 날짜를 임의로 만들지 않는다.
- 월별 평균은 최초 관측일이 월 중간이면 그 첫 부분 월을 제외한다. 그 뒤의
  사용이 없던 완료 월은 0으로 포함한다. 현재 월은 완료 월 평균에 넣지 않고,
  월말 예상치나 일할 보정도 적용하지 않는다.
- 필요한 완료 기간이 부족하거나 현재 기간의 시작부터 관측하지 못한 경우
  `THIS` subtotal은 보여 줄 수 있지만 `AVG`·Bar·비용 비교는 확정하지 않는다.
- 로컬 분석 범위는 최대 365일이다. 이 보존 범위의 모델별 합계와 토큰 범주는
  CLI의 `quotadeck usage --cumulative --models`로 확인할 수 있다.
- 파일 일부가 손상됐거나 읽히지 않으면 관측 가능한 subtotal은 `PARTIAL`로
  표시하되 비용과 놀람 단계는 확정하지 않는다. 유효 이벤트가 하나도 없으면
  0이 아니라 `N/A`다.

## LCD와 설정 앱 표시

누적 LCD는 잔여 리밋 화면의 큰 Bar 문법을 그대로 사용한다. Bar의 값은
`THIS 토큰 ÷ AVG 토큰 × 100`이며, 채움은 평균에 도달하는 100%에서 포화된다.
숫자는 잘라내지 않아 150%, 200%를 그대로 보여 주고 300% 이상은 `300%+`로
표시한다. 즉, 가득 찬 Bar라도 평균을 얼마나 초과했는지는 숫자로 구분된다.
정상 Bar 제목은 통화와 무관하게 월별 `M AVG`, 일별 `D AVG`로 표시한다. 작은
LCD에는 통화명과 한글을 넣지 않는다. 필요한 이력이 부족하면 `M BUILD`/`D BUILD`, 부분 기록이면
`M PARTIAL`/`D PARTIAL`, 원장을 사용할 수 없으면 `M N/A`/`D N/A`로 표시해
정상 평균과 구분한다.

Bar 아래에는 `THIS`와 `AVG`를 큰 글씨의 두 열로 배치하고, 첫 행은 토큰,
둘째 행은 선택 통화의 API 정가 환산치다. 비용 행의 좌측 시작에는 7×7 투명
픽셀 코인 아이콘을 둔다. 문자나 통화기호가 없는 KRW/USD 공통 아이콘이며
THIS/AVG 숫자, 분할선, 240×135 경계를 침범하지 않는다. 두 값은 비교하기
쉽도록 같은 단위를 쓰며, 비용에는 ASCII `K/M/B`만 사용한다.

선택적 collector 우선순위는 token-stats → native Codex/Claude parser →
ccusage 검증/fallback 이다. 설치는 선택 사항이다. 자세한 신뢰 경계는
[COLLECTORS.md](COLLECTORS.md)를 본다.

```text
THIS   AVG          THIS   AVG
0.6B   1.2B         0.6B   1.2B
1K     2K           0.4K   0.8K
```

왼쪽 비용 예시는 GUI에서 `KRW (만원)`을 선택한 경우이고 오른쪽은 USD 선택
예시다. 원화 금액의 기준 단위는 만원이므로 `1K = 천만원`, `1M = 백억`,
`1B = 10조`다. 이 범례는 KRW 선택 시 설정 GUI에 표시하고, LCD에는 통화
레이블이나 한글을 반복하지 않는다.

모델명과 모델별 사용량은 작은 LCD에 넣지 않는다. 데스크톱 설정 앱에는 선택
기간의 상위 2개 모델을 바로 표시하고, 해당 영역의 tooltip에는 전체 모델별
사용량을 표시한다.

### 캐릭터 반응 구간

| 선택 기간 `THIS ÷ AVG` | 화면 상태 | 연출 |
|---:|---|---|
| `< 1.0×` | `usage_below` | 여유 있고 차분함 |
| `1.0× – < 1.5×` | `usage_similar` | 살짝 놀라 주의를 기울임 |
| `1.5× – < 2.0×` | `usage_150` | 명확히 깜짝 놀람 |
| `2.0× – < 3.0×` | `usage_200` | 크게 충격받음 |
| `≥ 3.0×` | `usage_300` | 코믹하게 쓰러짐 |

Bar의 퍼센트 숫자는 **버림**해 캐릭터 단계보다 더 높은 값처럼 보이지 않게
한다. 예를 들어 실제 149.9%는 `149%`와 유사 단계로 표시된다. `AVG=0`일 때
`THIS=0`이면 0%와 중립 반응, `THIS>0`이면 `300%+`와 쓰러짐 반응을 사용한다.

## API 가격과 정가 환산

내장 가격표는 2026-09-11에 각 서비스의 공식 가격 페이지에서 취득한
USD/백만 토큰 정가 snapshot(`2026-09-11.2`)이다.

- OpenAI: <https://developers.openai.com/api/docs/pricing>
- Anthropic: <https://platform.claude.com/docs/en/about-claude/pricing>
- Cursor: <https://cursor.com/docs/models-and-pricing>
- xAI: <https://docs.x.ai/developers/pricing>

`quotadeck prices` 또는 `quotadeck prices --provider codex --model
gpt-5.6-sol`로 전체/선택 가격을 볼 수 있다. 이것은 매 실행마다 웹을
scrape하는 실시간 가격도, 청구서도 아니다. 날짜가 명시된 검토 가능한 정적
snapshot이며 가격이 바뀌면 catalog를 갱신해야 한다.

정가 환산치는 다음 조건을 모두 만족할 때만 선택한 **같은 기간**의 `THIS`와
`AVG` 두 값을 함께 표시한다. 한쪽만 계산된 금액은 표시하지 않는
all-or-nothing 방식이다.

1. 현재 인증 경로에 구독이 아닌 명시적 API-key 신호가 있다.
2. OpenAI/Anthropic 공식 endpoint를 사용하며 Azure, Bedrock, Vertex,
   Foundry, OpenAI-compatible gateway 또는 custom base URL 신호가 없다.
3. 모든 관측 이벤트가 모델에 귀속된다.
4. 모든 사용 모델과 사용된 토큰 범주의 단가가 snapshot에 있다.
5. 스캔이 partial이 아니고 입력 토큰 범주가 재분류 불가능 상태가 아니다.

하나라도 충족하지 않으면 일부만 더해 싼 금액처럼 보이지 않도록 두 기간 비용을
모두 미산정으로 두며 LCD에는 `--`로 표시한다. 구독, 혼합 인증, 불명확한
인증에는 API 정가를 적용하지 않는다.
Claude의 5분/1시간 cache-write TTL이 구분되지 않은 경우도 추정하지 않는다.
Cursor 가격 행은 base-model 정가 참고치일 뿐이며 Cursor Token Rate,
`cursorTokenFee`, 크레딧, 세금 또는 기타 플랫폼 비용을 포함하지 않는다.
long-context, fast, batch, 지역, 도구 호출 등 별도 요금도 포함하지 않는다.

설정에서 표시 통화를 **KRW (만원)** 또는 **USD**로 선택할 수 있다. 원화는 USD 정가
환산치에 사용자가 입력한 수동 환율을 적용하며 기본값은 **1 USD = 1,400원**이다.
이 환율은 인터넷에서 가져오거나 자동 갱신하는 실시간 환율이 아니다. 토큰과
마찬가지로 비용도 `THIS`와 `AVG`가 같은 단위를 사용한다. GUI에는
`1K = 천만원 · 1M = 백억 · 1B = 10조` 범례를 함께 표시한다.

누적 기간·통화·수동 환율 설정은 `config_version = 5`에 저장된다. 해당 필드가
없는 이전 설정은 월별·KRW·1,400원/USD 기본값으로 마이그레이션된다.

## 계정 귀속과 개인정보 한계

스캐너는 대화 본문이나 prompt/response 내용을 데이터 모델에 보존하지 않고
timestamp, model, token counters, 안정적인 event/session 식별자만 정규화한다.
로그와 화면에는 credential 값을 출력하지 않는다.

하지만 로컬 디렉터리 자체는 현재 로그인 account ID와 암호학적으로 결합된
원장이 아니다. 같은 프로필 디렉터리를 로그아웃 후 다른 계정으로 다시 쓰면
기록이 섞일 수 있다. 구독 로그인과 API key로 생성한 세션이 같은 로컬
history에 남아 있어도 과거 세션별 billing route를 확실히 분리할 수 없다.
현재 API-key 신호는 이 환산치를 보여 줄지 정하는 gate일 뿐, 과거 각 세션의
과금 경로를 증명하지 않는다. 따라서 `LIST $…`는 관측 토큰의 공식 API 정가
환산치이지 실제 지출액이 아니다. 로컬 합계와 정가 환산치는 기기 관측치이며,
정확한 계정별 비용이나 감사가 필요하면 공급자 관리자 usage/cost API 또는 실제
청구서를 사용해야 한다.

## 상태와 캐시

누적 스캔 결과는 반복 polling 비용을 줄이기 위해 짧게 캐시한다. 만료 뒤
재스캔이 실패하면 오래된 값을 최신인 것처럼 0으로 바꾸지 않는다. source가
없으면 `UNAVAILABLE`, 구현하지 않은 계정 범위는 `UNSUPPORTED`, 일부만 읽힌
경우 `PARTIAL`로 구분한다.
